# Setup Wunderkind Workflow

Bootstrap the durable Wunderkind project conventions without replacing host tooling.

## Primary owner

`wunderkind-product`

## Filesystem scope

`AGENTS.md`, `CONTEXT.md`, `.omo/`, and enabled documentation lanes.

## When to trigger

Use when a project needs shared context, workflow lanes, or PRD-flow choices.

## Anti-triggers

Do not use for generic repository initialization or implementation work.

## Process

1. Inspect existing project artifacts.
2. Preserve established conventions and choose the sparse workflow settings.
3. Record only the durable context and lane decisions needed by the project.

## Hard rules

Do not create duplicate host configuration or third-party assets.

## Review gate

Shared artifacts are coherent, minimal, and ready for a new task.
