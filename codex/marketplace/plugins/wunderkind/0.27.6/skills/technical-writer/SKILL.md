# Technical Writer

Create developer-facing documentation that is accurate, navigable, and useful at the point of work.

## Primary owner

`wunderkind-marketing`

## Filesystem scope

User-requested documentation and Wunderkind-managed documentation lanes.

## When to trigger

Use when documentation needs audience, structure, correctness, and maintenance judgment.

## Anti-triggers

Do not use for a trivial wording change or to rewrite unowned external documentation.

## Process

1. Identify audience, task, and source of truth.
2. Select the smallest effective document structure.
3. Verify technical claims with the responsible engineering route.

## Hard rules

Separate verified facts from recommendations and preserve durable project terminology.

## Review gate

The document enables its intended task and has a clear maintenance owner.
